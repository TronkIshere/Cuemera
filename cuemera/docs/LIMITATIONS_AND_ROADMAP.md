## 3. Needs a product decision

- **Decide a reset/retry policy for `coachingAiUnavailableProvider`.** **Partially resolved (thirteenth session):** a manual path now exists — `settings_screen.dart` surfaces a warning and a "Retry" action once `aiUnavailable` trips, which re-invokes `setEnabled(true)` and resets the flag (see `README.md` §14). **Still open:** there is still no *automatic* recovery — `model_lifecycle.dart`'s `ModelLifecycleManager` was written specifically to provide capped-backoff automatic retry (per the architecture audit that produced it) but is not wired into `ai_coaching_providers.dart` yet (audit migration step 7). Until that's done, a user who doesn't notice the new warning is still stuck until they happen to toggle the switch.
- **Gate the tenth-session debug logging behind `kDebugMode` before a release build.** `ai_gate:`/`coaching_phrase_generation:` (`voice_providers.dart`) and `pick_worst:` (`reference_comparison_engine.dart`) are plain `debugPrint` calls added for live diagnosis this session, left ungated — unlike `reference_picker_sheet.dart`'s existing painter debug logging, which is already `kDebugMode`-gated. **The twelfth session added a third ungated logger to this same list:** `LANDMARK_VERIFY`/the updated crop-redetect summary line in `reference_photo_crop_redetect.dart` are also plain `debugPrint`, not `kDebugMode`-gated.

- **Wire `ErrorReportingService` to a real remote sink.** It currently only retains the last 200 reports in memory (`FlutterError.onError`, `PlatformDispatcher.instance.onError`, `runZonedGuarded`, and every previously-silent `catch` all route through it) — reports don't survive app restart and never leave the device. A `TODO(remote-sink)` marks the extension point; needs a service chosen (Firebase Crashlytics, Sentry, custom backend) and an account/API keys before this can be wired up.
- **`enableClassification: false` on the live `FaceDetectorOptions` contradicts what this project's docs previously assumed** (`README.md` used to say classification was enabled downstream of Track 1's flag). As it stands, `eyesOpen`/`expression` are `null` for two independent reasons — the detector-level config *and* `FaceAnalyzer.enableEyeAndExpressionSignals = false` — meaning flipping the Track 1 flag back to `true` in the future would silently do nothing, since classification is already off one layer up. Needs a decision: either enable classification to match Track 1's original intent (re-enabling the eventual re-enable path), or update the docs/intent to reflect that classification is meant to stay off and remove the now-redundant `enableEyeAndExpressionSignals` flag.
- **Harden `CoachingPhraseModelService._buildPrompt()` against future prompt-length growth.** `maxTokens` was raised 128 → 512 this session after a real prompt (185 tokens) crashed the native inference process (see `README.md` §4) — but there's still no explicit length cap on the prompt itself, so a longer `fallbackPhrase` or a new `CoachingAttribute` down the line could reproduce the same crash. Needs a decision on approach: a rough character-based heuristic cap (cheap, approximate) vs. an actual tokenizer-based count (accurate, adds a dependency) before this class of bug is considered closed rather than just pushed further out.
- **Type `voice_providers.dart`'s `emphasisFor()` parameter properly.** It's currently written with no type annotation on purpose (`emphasisFor(severityBand)`) because `coaching_decision.dart`'s actual `severityBand` return type wasn't available when this was written — the string-matched `.name` call works if it's a plain Dart enum, but this should be tightened to a real type once that file is confirmed, both for compile-time safety and to catch a future rename of the enum's values.

## 5. Audit migration — what's still open (thirteenth session)

A standalone architecture audit produced an 11-step migration plan; steps 1–4 and 8–10 are implemented (see `README.md` §14) but **none of it is device-verified**, and several steps are explicitly incomplete:

- **Step 7 not done.** `model_lifecycle.dart`'s `ModelLifecycleManager` (retry/backoff, a real state machine instead of three loose booleans) exists as a standalone file but is not wired into `ai_coaching_providers.dart`. See item 3 above.
- **LLM output validation not wired anywhere.** `llm_output_validator.dart`/`llm_contract.dart` exist standalone (audit migration step 5–6) but neither listener (`voice_providers.dart` nor the new `voice_providers_v2.dart`) calls them — a Gemma-generated phrase that mentions the wrong direction, goes off-topic, or runs long is currently spoken as-is. This is a correctness gap, not just a polish item: the audit's whole rationale for the validator was "never speak an LLM phrase that says the opposite of what the deterministic decision computed."
- **`CoachingEligibility`'s confidence floor isn't enforced on the original listener.** `voice_providers.dart` (still the default, active path) speaks whatever `ReferenceComparisonEngine.evaluate()` returns regardless of `decision.confidence` — a low-confidence landmark-derived decision is spoken exactly as confidently as a rock-solid one. The new `voice_providers_v2.dart` listener does run `CoachingEligibility`, but three of its four inputs are stubbed (see below), so even there it's only the confidence-floor check that's doing real work today.
- **`voiceDirectorListenerV2Provider`'s `EligibilityContext` is stubbed, not real.** `subjectFullyInFrame`, `detectorsAgree`, and `temporallyEligible` are hardcoded `true` — `pose_analyzer.dart` computes real per-metric stabilizer eligibility internally (via `temporal_stabilizer.dart`, step 9) but doesn't surface it to the provider layer yet. **Do not enable the "Coaching v2 (experimental)" Settings toggle for real users** until this is wired and the path has had device soak time.
- **`_evaluateFaceYaw` still doesn't exist** in `reference_comparison_engine.dart`, despite `CoachingAttribute.faceYaw` existing in the enum and being referenced by `root_cause_engine.dart`'s head-orientation cluster. A `faceYaw` decision can never actually be produced.
- **No tests for any of this.** The audit's own §22 test plan (`landmark_trust_model_test.dart`, `temporal_stabilizer_test.dart`, root-cause/eligibility/action-plan unit tests) was never started. `reference_comparison_engine_test.dart` (existing, per `test/` in `FILE_REFERENCE.md`) almost certainly needs updating too — every evaluator's expected output now includes `confidence`/`controllability`, and the tier-selection tests need to account for root-cause collapsing.
- **Step 11 (flip the v2 flag, delete the old listener) intentionally not attempted** — correctly sequenced last, blocked on the eligibility-context and validator gaps above plus real device time, per the audit's own stated order.
