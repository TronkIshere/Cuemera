# AI_SESSION_CONTEXT.md

## 1. Read This First

Cuemera is a Flutter app that acts as an AI fashion photographer, directing the user in real time (via voice + visual cues) instead of asking them to copy a static pose. Before writing any code, check the relevant section below. If a file, token, or function is listed here, it already exists — read it, do not recreate it. Only ask the user for a file's exact current content if this document references it but you need to see the precise current implementation before editing it (this document describes shape and intent, not always byte-for-byte contents).

> **Migration complete.** The app has fully migrated from the old `PhotographyGoal`/rule-based direction system to a user-supplied **reference-photo comparison** system (`ReferenceProfile`, `ToleranceSettings`, `ReferenceComparisonEngine`, `comparison_math.dart`, `reference_providers.dart`, `reference_picker_sheet.dart`, `reference_image_analyzer.dart`). This replaced the entire goal-selection direction/scoring pipeline: users now pick a reference photo instead of a goal category, and the app directs/scores by comparing the live camera feed against that reference.
>
> The old goal-based system has been fully removed. `photography_goal.dart`, `goal_providers.dart`, `editorial_rules.dart`, and `goal_pill.dart` are **deleted** — do not reference them, and do not resurrect them without an explicit new request. A repo-wide search (`git grep` for `PhotographyGoal`, `GoalStyleProfile`, `selectedGoalProvider`, `styleProfileProvider`, `RuleCondition`, `rulesFor`, `GoalPill`, and the 4 filenames) confirmed zero remaining references in code — only this document and `PROJECT_STATUS.md` mention the terms now, as history.
>
> **Test coverage confirmed:** no test files exist anywhere in the project. `test/voice_director/priority_engine_test.dart` and `test/auto_capture_service_test.dart` do **not** exist — any earlier claim that they did was wrong. There is no test suite to run or maintain currently.

## 4. State Management Map

Riverpod throughout. Key provider families:

- **Scene/subject analysis** (`scene_providers.dart`): `subjectProfileProvider`, `sceneProfileProvider` (raw `StateProvider`s, written by listener providers), `trackingProgressProvider` (derived), `targetSubjectProfileProvider` (fixed ideal pose target for tracking-progress comparison — separate concept from the user-supplied `ReferenceProfile`).
- **Reference photo** (`reference_providers.dart`): `selectedReferenceImagePathProvider` → `referenceProfileProvider` (async, derived) → consumed everywhere direction/scoring/capture happens. `toleranceSettingsProvider` is independent, user-adjustable via sliders.
- **Direction** (`voice_providers.dart`): `nextActionProvider` (derived from subject/scene/reference/tolerance) → `voiceDirectorListenerProvider` (side-effecting, debounced TTS).
- **Scoring** (`score_providers.dart`): `currentScoreProvider` (derived, null-safe on missing reference).
- **Capture** (`capture_providers.dart`): `autoCaptureServiceProvider` → `shouldCaptureProvider` (derived bool) → `autoCaptureProvider` (side-effecting listener that triggers capture + builds shot) → `capturedShotProvider` (result sink, watched by `camera_screen.dart` to add to album).
- **Album** (`album_providers.dart`): `albumStateProvider` (`StateNotifierProvider`).
- **Theme**: `themeModeProvider` (`StateNotifierProvider`).

## 5. Project Conventions

- Design tokens only — no hardcoded hex/spacing (see Section 3).
- `copyWith()` pattern on all immutable model classes (`SubjectProfile`, `SceneProfile`, `ReferenceProfile`, `ToleranceSettings`).
- Riverpod `Provider`/`StateProvider`/`FutureProvider`/`StateNotifierProvider` as appropriate — async/nullable data (like `referenceProfileProvider`) is a `FutureProvider` and callers must handle loading/error/null, not just unwrap.
- `RepaintBoundary` around expensive custom-painted widgets.
- No test files exist in this project currently — confirmed via repo-wide search this session.

## 6. What NOT To Do

- Do not hardcode colors or spacing — use `AppColors`/`AppSpacing` tokens.
- Do not increase `EditorialMenuCard`'s `BackdropFilter` blur sigma or shadow layering back up without checking perf impact — it was deliberately reduced (sigma ~18 → ~7, two shadows → one) for a reported lag fix on `flutter run`.
- Do not assume a real `logo.png` exists — no such asset or `pubspec.yaml` declaration currently exists; the app relies on the `errorBuilder` text fallback.
- Do not resurrect `photography_goal.dart`, `goal_providers.dart`, `editorial_rules.dart`, or `goal_pill.dart` without an explicit new request — they were deliberately deleted after the reference-photo migration made them fully dead code, confirmed via repo-wide search.
- Do not confuse `goal_selection_screen.dart`/`goal_card.dart`/`EditorialMenuCard` (the app's Home screen — Shoot/Album/Settings cards) with the old `PhotographyGoal` rule system, despite the shared "goal" naming — the file/folder names are a naming relic from before the home-screen repurposing and are unrelated to the (now-deleted) goal system.
- Do not pass an `AsyncValue<ReferenceProfile?>` or a nullable `ReferenceProfile?` directly into `AutoCaptureService.debugConditionBreakdown()` or `.shouldCapture()` — both require a non-null `ReferenceProfile`; unwrap and null-check the async value first (see `debug_perf_overlay.dart` or `capture_providers.dart` for the pattern).

## 7. Known Open Gaps (not part of the completed migration)

- `dominantHue`/`warmthScore` on `ReferenceProfile` are permanently unused in live comparison until `SceneProfile` gains a live color-analysis field.
- `bodyRatio` never produces a directional instruction, only a neutral fallback phrase — by design, not a bug to fix without first deciding what the ratio should mean.
- `EditorialScore`'s visible breakdown does not include a pose category even though pose similarity gates capture — a real UX inconsistency, not yet resolved.
- `NSPhotoLibraryUsageDescription` was never added to iOS `Info.plist` despite `image_picker` being used by `reference_picker_sheet.dart` — gallery picking will likely crash/fail on iOS until this is added.
- `FocusRing`'s fade-out is non-functional (`AnimatedOpacity` hardcoded to `opacity: 1.0`) — minor cosmetic polish, not a functional bug.
- `AlbumState` is not persisted to Hive — restart clears the in-memory album (gallery copies on disk persist, but the in-app album list does not).
- `goalSelectionTitle`/`goalSelectionSubtitle` strings in `app_strings.dart` are dead, not yet removed.
- Album grid/detail image quality/smoothness issue — captures look sharp when taken but blurry in the album view, likely needs `cacheWidth`/`cacheHeight` hints on `Image.file` calls in `album_screen.dart`.
- The 3 top-navbar stub icons (`onAdjustmentsTap`, `onModeSelectorTap`) have no defined target behavior yet.
- `MemoryService` has no read-side consumer — `getFrequentCorrections()`/`getHabit()` are implemented but nothing calls them; wiring personalization into `reference_comparison_engine.dart` would be the natural target now.
