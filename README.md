# The Problem

Most pose and AI photography apps treat photography as a **pose-matching problem**:

```text
Reference → Copy → Capture
````

But your body isn't the same as the person in the reference.

The lighting isn't the same.

The camera isn't in the same position.

The background isn't the same.

Your expression isn't the same.

So what happens?

You end up trying to become a human mannequin.

**That's not direction. That's mimicry.**

A real photographer works differently.

They look at **you** and decide what matters most **right now**.

If your shoulder looks awkward, they fix your shoulder.

If your expression is wrong, they fix your expression.

If the lighting is bad, they fix the lighting.

If everything is good except your framing, they don't give you five unrelated instructions.

They tell you **one thing**.

You change.

They look again.

Then they adapt.

# How Cuemera Works

Cuemera continuously observes the camera scene and builds an understanding of:

# 🧠 Under the Hood

Cuemera is built as an **11-layer AI photography pipeline**.

Not because eleven layers sound impressive.

Because taking a good photograph involves much more than detecting a skeleton.

```text
Goal Understanding
        ↓
Human Understanding
        ↓
Scene Understanding
        ↓
Editorial Brain
        ↓
Photographer Brain
        ↓
Direction Engine
        ↓
Tracking Engine
        ↓
Capture Engine
        ↓
Quality Engine
        ↓
Album Director
        ↓
Memory Layer
```

Each layer answers a different question:

| Layer               | Question                                  |
| ------------------- | ----------------------------------------- |
| Goal Understanding  | What are we trying to create?             |
| Human Understanding | What is the person doing?                 |
| Scene Understanding | What's happening around them?             |
| Editorial Brain     | What makes this particular photo good?    |
| Photographer Brain  | What matters most right now?              |
| Direction Engine    | What should I tell the person to do?      |
| Tracking Engine     | Did they actually do it?                  |
| Capture Engine      | Is the moment ready?                      |
| Quality Engine      | Was the resulting photo good?             |
| Album Director      | What should we shoot next?                |
| Memory Layer        | What can we learn from previous sessions? |

Together, these layers turn camera input into something much closer to a photographer's judgment.

# ⚡ On-Device AI

The core photography loop is designed to run **on-device**.

### Tech Stack

* **Flutter** — cross-platform mobile application
* **Dart** — application logic and AI orchestration
* **Riverpod** — state management
* **Google ML Kit** — pose detection, face detection, selfie segmentation
* **Flutter TTS** — real-time voice direction
* **Hive** — local persistence
* **Gemma / local AI components** — supporting intelligent coaching behavior where applicable

The phone can continuously observe and react without requiring a cloud request for every camera frame in the core photography loop.

That matters for two reasons:

### Speed

A photographer can't wait three seconds for the cloud to say:

> "Move your shoulder."

### Privacy

A camera pointed at your face is personal.

The core perception loop is designed around **on-device processing**.

**Your photographer lives in your pocket.**

# Getting Started

## Prerequisites

* Flutter SDK `^3.8.1`
* Dart 3.8+
* Android: minSdk 21+
* iOS: 13.0+
* **A physical device is strongly recommended**

Camera processing, ML inference, TTS timing, thermal behavior, battery consumption, and real-time performance cannot be meaningfully evaluated on a simulator/emulator.

## Installation

```bash
git clone <repository-url>
cd cuemera

flutter pub get
flutter run
```

## Development

Run static analysis:

```bash
flutter analyze
```

Run tests:

```bash
flutter test
```

Run on a connected Android device:

```bash
flutter devices
flutter run
```
